## Purpose

This handoff defines the Suppliers-owned business-health contract for supplier stock traceability into Warehouse, Catalog, and FlipFlop. It separates proven synthetic traceability evidence from the missing real supplier procurement facts that must exist before any scheduled monitor, supplier onboarding, production import, Catalog write, or Warehouse stock mutation can be treated as business health.

## Intent Preservation Chain

- Vision: Suppliers is the controlled, validation-first supplier import service for supplier product and stock intake.
- Goal Impact: Stock traceability can be monitored as business health only when Suppliers evidence proves validated supplier candidates, idempotent import orchestration, Catalog product identity checks, and Warehouse-owned stock authority without exposing credentials or importing live supplier data.
- System: Suppliers owns supplier connection metadata, runtime credential references, import jobs, supplier payload validation, category mapping, idempotency evidence, and Warehouse reconciliation intent; Warehouse owns stock and logistics truth; Catalog owns product truth and projects Warehouse availability to FlipFlop.
- Feature: Supplier stock traceability business-health evidence envelope consumed by downstream monitors.
- Task: Publish a Suppliers-owned handoff that records synthetic proof, missing real supplier facts, monitor consumption rules, validation evidence, blockers, and parallel follow-up workstreams.
- Execution Plan: Source-only documentation plus a narrow verifier. No runtime mutation, deploy, supplier credential inspection, live supplier import, Catalog write, Warehouse stock mutation, Kubernetes change, or cleanup mutation is allowed in this lane.
- Coding Prompt: If later implemented, a monitor must read only sanitized Suppliers evidence artifacts and API summaries; it must not read secrets, private supplier endpoints, raw supplier payloads, or execute imports.
- Code: This handoff is documentation-owned. The optional verifier validates required handoff markers only.
- Validation: `node scripts/verify-business-health-suppliers-contract.js` and `git diff --check`.

## Scheduled Monitor Consumption Rules

A scheduled business-health monitor must consume Suppliers evidence as a read-only contract:

1. Read sanitized Suppliers evidence summaries, checked-in docs, generated manifests, and allowed health endpoints only.
2. Verify that runtime-complete claims have both the runtime report and evidence manifest, and that `verify-stock-traceability-completion.js` previously accepted the bundle.
3. Treat the 2026-06-24 synthetic runtime-complete bundle as synthetic traceability proof, not real supplier procurement evidence.
4. Report `[MISSING: ...]` markers unchanged until the owner supplies reviewed facts.
5. Fail closed if an evidence envelope contains bearer tokens, API keys, passwords, private keys, raw supplier payloads, private supplier endpoint values, unredacted response bodies, or customer data.
6. Fail closed if a monitor path requires supplier credentials, live supplier imports, Catalog writes, Warehouse stock mutations, Kubernetes changes, deploys, or cleanup mutation.
7. Keep Suppliers, Warehouse, Catalog, and FlipFlop authority boundaries explicit: Suppliers validates and orchestrates; Warehouse owns stock/logistics; Catalog owns product truth and projection; FlipFlop consumes projected truth.
8. Separate monitor statuses for synthetic runtime, real supplier readiness, scheduled import execution, mapping completeness, and downstream projection. Do not produce one aggregate "healthy" status when real supplier facts are missing.

Recommended status vocabulary:

| Status | Meaning |
| --- | --- |
| `passed-synthetic-runtime` | Verified synthetic runtime-complete bundle exists and current docs reference it. |
| `blocked-real-supplier-facts` | One or more `[MISSING: ...]` procurement facts remain. |
| `blocked-approval` | Required owner approval for import, deployment, Catalog write, Warehouse mutation, or cleanup does not exist. |
| `failed-evidence-safety` | Evidence contains forbidden secrets, raw payloads, private endpoints, or mutation instructions. |
| `not-applicable` | Real scheduled procurement has not been onboarded yet. |
